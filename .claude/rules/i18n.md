# Strings

`apps/game/src/presentation/i18n/` holds one object per locale;
`packages/core/src/i18n/` holds the machinery that reads them. **`dictionary-en.ts`
is the reference** — `TranslationKey` is `DotPath<typeof EN_DICTIONARY>` and
`dictionary-fr.ts` is typed against it, so a key added to English and forgotten
in French does not compile, and neither does a typo at a call site.

**One user-visible string lives outside the dictionaries**, and it is the head
of a served document: `presentation/head/document-head.ts` holds the `title`,
`description` and `og:` copy for the fourteen prerendered pages. They are
written at build time by a Node script with no React and no provider, so a
dictionary lookup is not available to them — the reasoning is in
[`docs/plans/19-locale-urls.md`](../../docs/plans/19-locale-urls.md). Nothing a
component renders belongs there.

**A tab title that is not one of those fourteen is an ordinary string**, and
goes in the dictionary like any other. `/host/:code`, `/play/:code` and the
not-found page are served by the SPA fallback rather than by a prerendered
document, so nothing writes their head at build time and they inherit the
*English* home page's — which is what a French room's tab said until
`room.documentTitle` existed. The split is which side of the mount the copy is
composed on, not that it happens to end up in `<title>`.

A key is the dotted path to a leaf of a nested object, with two consequences:

- **A branch cannot also be a leaf.** `host.answerWindow` was both a label and
  the parent of `host.answerWindow.none`; it is `host.answerWindow.label` now.
  When a group needs a name of its own, that name is a child.
- **The full key is written nowhere.** `grep 'error.room_not_found'` finds the
  call site, never the string. Search for the last segment, or walk down from
  the prefix.

## Adding a string

1. Add the key to `dictionary-en.ts`, namespaced by the prefix test below.
2. Add it to `dictionary-fr.ts`. The compiler will insist.
3. Write placeholders by the table. A missing *value* renders the placeholder
   rather than throwing, so it surfaces in the browser pass.

| Written | The caller passes | Use it for |
|---|---|---|
| `{name}` | a `string` | a nickname, a room code, a build hash |
| `{n:number}` | a `number` | any number in a sentence |
| `{n:plural}` | a `number` | a number the sentence **agrees with** |
| `{n:relative}` | a `number` | a moment relative to now — negative is the past |
| `{x:displayname}` | a `string` | a language or region code, written as a word |

> **`packages/i18n/` is not this project's code.** Its `src/` is a verbatim
> copy of `@adrienlcp/i18n` in `C:/git/toolkit`, shared with Stargazer. Never
> edit it in place: change the library there, run `pnpm validate` in the
> toolkit, then `pnpm toolkit:sync` here. `pnpm toolkit:check` fails when a
> copy has drifted, and `pnpm validate` runs it. The library's own README sits
> inside `src/`.
>
> It is a workspace package rather than a folder, and it carries the name it
> would have on npm, so the day the toolkit is published nothing but a
> `package.json` changes. Everything around `src/` — the manifest, the
> tsconfig, the vitest config, the README saying not to edit it — is Taverla's.

`{at:date}`, `{items:list}`, `{x:enum}`, `{x:relative}` and `{x:displayname}`
exist and are unused so far. `plural`
and `enum` carry alternatives, so they take a second argument through
`defineTranslation` — and `defineDictionary` refuses a bare string that
declares one, rather than letting the map go missing and the count print raw. A
message with nothing to say to the formatter is a plain string, called with no
second argument.

```ts
'host.seconds': '{seconds:number}s',
'host.roundCount': defineTranslation('{count:plural}', {
  plural: { count: { one: '{?} round', other: '{?} rounds' } }
}),
```

`{?}` is where the formatted number lands inside a form — a form may leave it
out entirely, which is how `player.points` renders the bare word beside a score
the markup prints itself.

**A count earns `plural` when any locale changes a word because of it.** Not
English — *any*: French counts 0 as singular where English is plural at 0, so
the reference declares the plural the moment one of them inflects and English
writes nothing but `other`. `packages/core/src/i18n/translator.test.ts` holds it
red.

## Which prefix — one question decides it

> **Would the second game display this string unchanged?**

If yes it is **shell**: `join.*`, `host.*`, `player.*`, `round.*`, `buzz.*`,
`error.*`, `connection.*`, `menu.*`, `preferences.*`. If no it takes the game's
name — `blindtest.*`, `buzzer.*`, `quiz.*`, `lefake.*` — even when the host
console is what renders it, because `host.*` names a *screen* and a screen shows
both kinds. A game's prefix is its `GameKind`, and `gameNameKey`,
`gameTaglineKey` and `gameDescriptionKey` build `` `${ShelvedGame}.name` `` and
its siblings, so putting a game on the shelf does not compile until both locales
can name it, pitch it and describe it.

Every argument this test has already settled, and what each one moved, is in
[`../../docs/game-catalogue.md`](../../docs/game-catalogue.md).

## The voice: a tavern, never a dispositif

**Never name the device, and never recite the setup.** No *téléphone* / *phone*,
and no string whose content is *one screen shows this, the others answer on
that*. It is cold — it describes the plumbing to people who came for an evening —
and it is *false*: the screen running the room can be a phone and a player can be
on a laptop. *Écran* itself is fine, and is the product's own neutral word for
whichever machine is hosting; it is *les téléphones de tout le monde* that
assumes. Say what the room does, not what it runs on. The one exception is the
document head — the titles and descriptions in
`apps/game/src/presentation/head/document-head.ts`, read by people with no room
in front of them.

The room is a tavern, and each locale reaches that register with its own words
rather than by translating the other's:

| Concept | French | English |
|---|---|---|
| room | la table | the table |
| host | l'aubergiste | the innkeeper |
| round | la tournée | a round — already the pun, left alone |
| roster | la tablée | the table |
| join | prendre place · pousser la porte | pull up a chair · walk in |
| start | À table ! | Gather round |
| close the room | lever la table | clear the table |

Two things this does **not** license. A **game's** own vocabulary stays behind
its prefix — *trois notes* is `blindtest.*`, and a quiz pitch may not borrow it.
And **a control still names its outcome**: the register lives in headings, empty
states, waits, errors and pitches, never at the cost of a button a standing host
has to hit in one go.

An error keeps the register and still owes a way out — *Ça a cassé de notre
côté. Réessaie.*, never *Quelque chose a cassé côté serveur.* Internal words —
*console*, *reveal*, *manche*, *côté serveur* — are the tell that a string was
written from inside the code.

## Hold a key, never a rendered string

An error stored in state as `translate(…)` output freezes in whatever locale was
active when it was set. Store `{ key, values }` and translate at render;
`join-with-code.tsx` does this, and switching locale with an error on screen is
how you check it. Hoisting a rendered string to module scope freezes it the same
way, for the life of the tab.

A key that travels without its values — through `useState`, a
`Record<Status, …>`, a prop — is typed `PlainTranslationKey`, because whoever
reads it back has nothing to give it.

## An enum reaches a user through a function

`protocolErrorKey`, `apiErrorKey` and `buzzBlockerKey` return
`BuiltKey<\`error.${ProtocolErrorCode}\`>` and friends. Both halves earn their
place: the template literal lets the caller use the no-values overload, and
`BuiltKey`'s constraint is what fails to compile when `error-code.ts` is widened
before both locales have the string. Do the same for the next enum, rather than
a `switch`.

**The server's `message` field is never rendered.** It is English, written for a
log. The user sees the translation of `code`.

## The locale is in the URL, except in a room

`/fr/…` and `/en/…` lead every page a crawler reaches, and `applyInitialLocale`
reads the locale out of the *served path* before storage and before
`navigator.languages` — a link shared in one language opens in that language,
whoever follows it. A room's path names none on purpose, which is why those two
fallbacks stay and why switching language inside a room is state alone:
navigating out of `/host/:code` closes the socket, and the server cannot tell
that from a closed tab.

So a link is built from `homePathFor`, `creditsPathFor` or `gameHomePathFor`,
with the locale from `useI18n`. A bare `paths.home` in an `href` is the bug
this replaced — it compiled, and it dropped the reader into whichever language
their browser preferred.
