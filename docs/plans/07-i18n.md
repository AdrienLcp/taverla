# Stage 07 — Language and appearance

**Goal.** Make the UI speak English and French, and let it be read in a dark
living room or a bright kitchen.

**State: done.** Run out of order, before stages 01–06, for the reason the
original plan gave: strings and colours are cheap to route through a layer
before a design pass hard-codes them, and expensive after.

## What shipped

**A dictionary layer, no library.** `apps/game/src/presentation/i18n/` holds one
object per locale. `dictionary-en.ts` is the reference: `TranslationKey` is
`keyof typeof EN_DICTIONARY`, so a missing or misspelt French string is a
compile error rather than a blank in the UI. Interpolation is `{name}` and a
`Record<string, string | number>`; there are no plural rules worth a dependency
yet. Add one when dates or gendered agreement appear, not before.

**Locale negotiation lives in `packages/core/src/i18n/locale.ts`,** with a test.
`pickLocale(navigator.languages)` drops the region — `fr-CA` reads the French
dictionary — and takes the first *supported* tag rather than the first tag. A
stored choice wins over the browser; English is the fallback when nothing
matches.

**Server error codes are translated client-side,** as the original plan
recommended. `protocolErrorKey(code)` returns a `TranslationKey`, so widening
`error-code.ts` fails to compile until every locale has the string.
`ProtocolErrorMessage.message` is no longer rendered anywhere — it is a
developer-facing detail again.

**Light and dark, decided in CSS.** `_tokens.sass` holds two palettes as mixins.
`:root` is dark; `[data-theme='light']` and
`@media (prefers-color-scheme: light) :root:not([data-theme='dark'])` are light.
`ThemeProvider` stamps `data-theme` **only for an explicit choice**, which is
what leaves the system default resolvable before any script has run — a
JavaScript-decided theme cannot apply until after the first paint, and that gap
is the flash.

**A preferences bar on every screen.** Two `SegmentedControl`s (a react-aria
`RadioGroup`) in a footer rendered by `AppShell`, so the phone that arrived
straight from a QR code can still switch language. Both choices persist in
`localStorage` via `infrastructure/storage/preferences-storage.ts`.

> Superseded. The footer became `AppMenu` — the same two controls, plus the
> connection and a link home, behind one trigger in the top-right corner. A bar
> that costs every screen 90 px of height for two settings nobody changes twice
> an evening was the wrong trade, and it left no room for the exits.

## Where this diverged from the plan

- **English is the fallback, not French.** The plan said "`fr-FR` as the
  default". Detection makes that mostly moot: a French phone gets French without
  being told. English is what a Spanish or German browser lands on, which is the
  more useful fallback for a guest. One line in `locale.ts` if that call is
  wrong.
- **A locale picker was in "out of scope".** It stopped being optional the
  moment both locales existed: a phone that scanned a QR code never passes
  through a settings screen, so the switch has to be on every surface.
- **Language names are not translated.** `English` / `Français`, always. Someone
  hunting for their language in a UI they cannot read has only the word itself.

## The cost, measured

The initial payload went from **109 kB gzipped to 129 kB**. Roughly 4 kB is the
i18n and theme layer; the remaining ~15 kB is react-aria's `RadioGroup` landing
in the eager chunk because the preferences bar renders on every route.

The lazy route split is untouched — the player chunk is still ~6 kB and the host
chunk ~20 kB. If the initial payload ever becomes the problem, the chrome is
what to defer: it is now `AppMenu`, whose popover pulls react-aria's overlay
code into the eager chunk on top of the `RadioGroup` measured above. Deferring
it needs the trigger's box reserved first, or the corner shifts when it mounts.

## Verified in a browser

At 414 px and 1920 px, on the join, host, player and nickname screens:

- both locales, switched live, including an error message already on screen —
  errors are held as keys, so they follow the switch
- all three theme paths: `data-theme="dark"`, `data-theme="light"`, and no
  attribute resolving through `prefers-color-scheme`
- **the socket is not remounted by a locale or theme switch** — counted by
  patching `window.WebSocket`; it stays at one across both

## Still open
